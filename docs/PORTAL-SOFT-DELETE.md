# 中台逻辑删除

用户、部门、虚拟 Key、客户端版本和计费配方采用 `DeletedAt` 逻辑删除。EF Core 全局查询过滤器隐藏已删除记录，管理列表、授权选项、登录以及版本检查/下载使用同一过滤规则。历史账单、审计及版本安装文件保留；不提供恢复入口。

- 用户：不能删除当前登录账号；删除后停用账号，撤销桌面会话与令牌，删除个人配方绑定，并产生 `user.deleted` 同步消息。
- 部门：仍有未删除用户（包括停用用户）时拒绝删除；删除后清除部门配方绑定。
- 虚拟 Key：先在 LiteLLM 禁用真实凭据，再标记删除；网关失败时保留原记录。
- 版本：停止分发并取消该版本的强制更新要求，不删除已有安装文件，也不降级已安装客户端。
- 配方：仍有个人或部门绑定时返回 HTTP 409，即使配方已停用也不能删除。与绑定写入使用共享锁避免并发删除后继续绑定。

原有唯一标识（工号、邮箱、部门编码、Key 别名、版本/架构、配方名称）仍保留，不能通过删除重建同标识记录覆盖历史。

删除入口统一使用 Ant Design `Modal.useModal().confirm`。取消不会发送删除请求；新入口在异步请求完成后关闭，失败时显示错误并允许重试。

已有数据库由 `DatabaseSchemaInitializer`、`TokenBillingSchema` 启动时执行幂等 ADD COLUMN 增量升级，新增可空 `DeletedAt` 字段；历史行默认为未删除。本次不执行生产升级或部署。
