## 2. 更新内容

### DSH 客户端

1. 修复配置多个敏感词时的拦截问题，支持多个敏感词的解析与匹配。
2. 调整 Windows 任务栏图标的裁切与尺寸，改善图标显示效果。
3. 增加系统托盘常驻能力，窗口关闭后可通过托盘重新打开或退出。
4. 调整加载动画，让副标题“把繁琐交给我，把专注留给你”更早出现。
5. 接收 AIGC 指定范围内的公告，在 DSH 内部弹窗展示，支持阅读和确认回执。
6. 接入 AIGC 灰度版本检查、下载和重启安装流程。
7. 支持内网未签名安装包自动更新，无需配置代码签名证书和硬件 Token。

### AIGC 管理后台

1. 新增公告管理，支持草稿、发布、撤回、有效期和重要公告设置。
2. 新增客户端灰度发布管理，支持版本草稿、安装包上传、指定范围、发布、暂停与恢复。
3. 公告和灰度版本支持按用户、角色、部门组合指定范围，重复人员去重。
4. 统一公告、客户端版本、虚拟 Key 和模型授权中的用户、角色、部门选择与搜索样式。
5. 虚拟 Key 和模型授权界面统一使用“部门”概念，虚拟 Key 支持角色授权。
6. 优化公告详情与回执，完整展示正文、有效期、回执统计和送达/已读/确认时间；回执每页 10 条。
7. 公告列表、版本列表与客户端上报表增加分页；操作审计默认每页 10 条。
8. 公告与客户端版本操作栏采用角色管理同款图标按钮，悬停显示操作名称。
9. 公告、版本、上报及回执表格的表头、数据和操作按钮统一居中。
10. 调整灰度管理中两个表格的间距及弹窗滚动布局，避免搜索框被遮挡。

## 3. 实现逻辑

### 3.1 敏感词拦截

AIGC 管理敏感词策略，DSH 在提交用户提示词时通过 prompt admission 环节进行检查。多个敏感词被拆分成独立规则，再对提示词文本进行匹配；命中后拒绝提交。策略获取与更新接入当前托管身份流程，减少策略变化后继续使用旧配置的问题。

### 3.2 Windows 图标与窗口生命周期

任务栏图标使用居中正方形裁切，并缩放至 256 × 256；托盘图标使用较小尺寸。关闭主窗口时保留客户端进程，通过托盘入口重新打开窗口；需要彻底退出时使用托盘退出操作。加载动画的副标题提前进入显示阶段。

### 3.3 公告推送与回执

管理员保存公告内容、有效期、重要标记及接收范围。服务端将用户、角色和部门选项解析为实际人员名单，去重后保存接收人快照。

DSH 使用当前登录用户的凭据轮询公告接口，获取已发布、处于有效期且分配给自己的公告。公告通过客户端内部弹窗展示，不再调用 Windows 系统公告弹窗。客户端记录送达、阅读和确认状态，服务端维护回执时间；管理员在详情页查看统计及分页回执。

公告和版本的接收人是保存时的快照，后续角色或部门成员变化不会自动扩展已有名单，需要重新保存范围。

### 3.4 客户端灰度升级

完整流程：

1. 管理员创建版本草稿，填写实际安装包版本号与 Windows 架构，并选择测试范围。
2. 上传 `.exe` 安装包及可选的同名 `.exe.blockmap`。
3. 服务端保存文件并计算 SHA-512，根据安装包信息生成更新清单。
4. 发布后，DSH 使用当前登录身份检查是否分配到更高版本。
5. 命中目标范围时，服务端返回对应版本的更新源路径；客户端复用现有 Electron 更新机制完成下载、文件校验、用户确认和重启安装。
6. 客户端上报设备、当前版本和更新状态，后台通过客户端上报列表跟踪结果。

管理页面采用人员范围灰度，首期不提供百分比随机分配。暂停发布阻止新的服务端下载，不会撤销已下载的安装包，也不会将已升级客户端自动降级。

### 3.5 内网未签名更新

使用以下命令打包：

```powershell
pnpm run package:desktop:win:x64:unsigned -- --build-version auto
```

`auto` 依据本地产物生成递增构建版本号，跨电脑构建时仍需核对版本唯一性。未签名托管包保留 `app-update.yml` 和 AIGC 更新入口，省略证书发布者校验，但继续保留登录鉴权、灰度范围控制和 SHA-512 文件校验。

当前打包后端地址为：

```text
https://aigcbackend.boschhuayu-steering.com
```

不需要给每个安装包手动填写下载地址。AIGC 根据实际发布版本向目标客户端下发更新路径；本地产物 `nightly.yml` 无需上传，服务端自行生成更新清单。

旧客户端如果没有该更新配置，或已经绑定签名发布者，需要先手动安装一次本次未签名基础版本。之后生成更高版本，通过 AIGC 发布，才能验证自动升级。开发模式 `dev:desktop` 不执行安装升级。

### 3.6 文件存储与数据库

数据库保存公告、版本、人员范围、回执、文件元数据和客户端上报。安装包文件本体保存到文件存储目录，不写入数据库。

服务器新增参数：

```text
DesktopReleases__Root=/var/lib/aigc-hub/desktop-releases
```

本次 Kubernetes 更新通过 `api-update.patch.json` 配置该环境变量，复用 `aigc-dsh-uploads` PVC 的 `desktop-releases` 子目录。初始化容器创建目录，API 挂载后读写；Pod 重建不会清空持久卷文件。Nginx 上传限制调整为 `2100m`，服务端安装包上限为 2 GiB，差分文件上限为 32 MiB。

API 启动时执行增量建表和字段补充，保留现有用户、角色、部门和其他业务数据。管理员需重新登录以取得新增管理权限。

### 3.7 管理界面与分页

用户、角色、部门选择复用统一组件，支持搜索、跨页选择、已选项展示和移除，候选项每页 12 条。公告、版本、客户端上报和公告回执表格默认每页 10 条；操作审计采用服务端分页，默认每页 10 条。公告、版本与回执当前采用前端分页，客户端上报接口返回最近 1000 台设备。

操作栏复用角色管理的图标按钮样式，通过 title 和 aria-label 提供操作名称。页面针对各表格统一居中对齐，不改变其他管理页面的表格样式。
