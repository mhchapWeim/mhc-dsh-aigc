# DSH 失败日志

本功能包含 DSH 本地日志与后台上传、AIGC 接收和去重、管理页面。客户端和中台均默认保留 7 个 UTC 自然日。中台数据存储在 PostgreSQL `aigc_hub."DshFailures"`，不需要额外挂载日志目录或配置环境变量。

## 使用

1. 更新 AIGC API 和门户，并重新打包、安装 DSH。
2. API 启动时自动创建新增表、索引与 `diagnostic.manage` 权限，自动授予平台管理员。已有管理员需重新登录，以获取新的权限声明；其他角色可在角色管理中授权“DSH 失败日志”。
3. DSH 登录 AIGC 后自动在后台上传。正常每 30 秒检查，积压每秒处理一批，单批最多 20 条；断网后指数退避，最大间隔 15 分钟。未登录时只在本机保存。
4. 中台“平台配置 → DSH 失败日志”打开 `/admin/dsh-failures`。可以按工号或姓名、设备 ID、完整版本、错误类型、发生时间查询，查看错误信息、操作上下文和关联会话，下载单条 JSONL。

## 运行约束

- 上传使用现有 DSH 登录令牌，服务器以认证身份确定账号。不同账号分别保存本地上传进度；退出登录会取消在途请求。
- 服务器确认整批事件后才保存进度。重启或网络超时可能重发；数据库唯一索引按用户和事件 ID 去重。
- 已过期的迟到事件确认接收但不保存。中台查询立即排除过期记录，后台每小时清理一次；启动一分钟后首次清理。
- 本地日志仍保留，已上传不会立即删除。断网超过保留期限或日志达到容量上限可能删除尚未上传的记录。
- 请求体、工具参数和会话历史不作为诊断字段上传。客户端和服务器均脱敏常见凭据；自由格式错误可能包含业务数据。无法取得原始登录名的记录归属当前认证上传账号。
- 后台上传失败不会再次写入失败日志，避免上传错误自我累积；本地日志和手动导出继续可用。

## 接口

| 接口 | 认证 | 用途 |
| --- | --- | --- |
| `POST /v1/desktop/diagnostics` | DSH 登录令牌 | `{ "events": [...] }`，返回 `acceptedEventIds` |
| `GET /api/dsh-failures` | 中台 JWT + `diagnostic.manage` | 分页查询，参数 `user/device/version/category/from/to/page` |
| `GET /api/dsh-failures/{id}` | 同上 | 查看详情 |
| `GET /api/dsh-failures/{id}/download` | 同上 | 下载单条 JSONL |

接收限制为每批 20 条、请求体 1 MiB；服务器只保留允许的字段。默认查询每页 20 条。
