# 应用注册中心（临时直录）

入口：后台 → 协作与发布 → 应用管理（`/admin/registry`）。页面默认打开「注册应用」；「流程发布应用」管理已发布完成记录的启停。管理权限复用 `category.manage`，避免另开默认授权。

填写中文/英文名称和简介、已有分类下拉、负责人、HTTP/HTTPS 访问 URL、显示排序、启用状态及访问范围。中文名称和简介离开输入框时使用当前用户获授权的默认模型自动翻译；英文可修改，手工修改不会被后续自动回填覆盖。“重新翻译”可主动替换英文。模型未配置或连接失败时提示手动填写，不编造译文。

启用应用显示在所有已登录且有 `portal.view` 权限用户的应用集合中；停用后隐藏。部门授权和个人授权取并集，默认“指定部门及个人”，无授权对象时无人可进入。可显式选择“所有已登录用户”。应用卡片、进入按钮和键盘激活均在进入时请求后端校验当前用户及实时授权；普通目录响应不暴露注册应用 URL。登记应用显示“注册应用”，不冒充审批通过。

这是门户入口授权。目标应用若允许用户直接输入 URL 访问，仍须自行验证其登录及访问权限；本功能不代理目标应用流量。

数据库：`aigc_hub.RegisteredApplications`、`RegisteredApplicationGrants`；新增表由启动时 `DatabaseSchemaInitializer` 增量创建，已有发布申请保持原逻辑。注册表预留可空 `PublicationRequestId`，用于后续审批接入；本期不自动导入审批数据。

上线需同时更新 API 和 Portal，启动 API 后确认增量表已创建。无需新增依赖。自动翻译依赖现有“模型管理”中当前管理员可用的默认模型；本地验收中发现模型连接被拒绝，需恢复连接才能完成真实翻译验收。

验证：后端 HTTP 集成测试覆盖所有人可见、URL 隐藏、默认拒绝、部门/个人授权、撤销、所有人访问、停用、管理权限和非法输入；前端覆盖自动翻译、手工英文保护、失败提示、保存授权、门户双语和授权跳转。


## 点击率报表与二级分类（2026-11-04）

“报表管理”下提供“点击率报表”（`/admin/click-reports`），与“计费报表”并列，沿用 `category.manage` 权限。报表覆盖所有注册应用，含停用应用，可搜索、分页、按日/周/月/年点击数排序。应用集合卡片展示相同的统计结果。

- 统计口径：中台鉴权成功的“进入应用”点击；不代表外部目标页面加载成功或应用内部访问次数。未授权、停用、GET 权限探测、收藏操作均不计数。
- 时间口径：服务端时间、北京时间自然日、周一 00:00 开始的自然周、自然月、自然年。此前没有原始点击事件的历史周期从 0 开始。
- 客户端只在点击时 POST `/api/catalog/registered-apps/{id}/access`，附 UUID `visitId`；先鉴权再返回地址，不创建空白页。HTTP 内网浏览器缺少 `randomUUID` 时使用 `getRandomValues` 生成 UUID。
- 服务端以应用为粒度加 PostgreSQL 事务 advisory lock，同一用户/应用 3 秒内只计一次；应用/用户/visitId 唯一约束保证请求重放不会重复计数。固定数量的本进程锁避免无限增长。不同用户和不同应用分别统计。
- `ApplicationClicks` 保留原始事件。`ApplicationClickAdjustments` 按应用/周期/周期起点保存调整差值。编辑注册应用时只提交被修改的周期，调整后新点击继续累加；周期切换后自动使用新周期的数据，不继承旧周期调整。
- 每次调整与应用编辑同事务提交，`OperationAudits` 的 `application.clicks.adjust` 保存操作者、调整前值、目标值和周期起点。展示值允许独立调整，因此各周期不强制大小关系。
- 报表使用一致性读取；进入响应返回后端权威计数，卡片直接使用该值，不自行累加过夜的旧统计。

分类新增可空 `ParentId`，只允许两级，禁止自引用、循环和将有子分类的一级分类移到其他分类下；含二级分类或关联应用时不能删除。分类管理可选择上级分类创建、修改二级分类；注册中心、发布申请以“一级 / 二级”选择绑定。应用集合保留一级导航，卡片展示二级分类并可按二级分类筛选。现有一级分类与应用绑定保持兼容。

数据库由 `DatabaseSchemaInitializer` 增量创建新表、索引和 `Categories.ParentId`；已在受保护的本地独立 PostgreSQL 测试库验证旧结构升级及重复执行。未部署生产。

## 倍率仅展示（2026-11-04）

模型 `Multiplier` 文本继续保留并显示。AIGC 配额结算只使用上游实际 `totalTokens`，统一按 1 倍计入周额度；新预记账保存有效计费倍率 1，旧的待结算请求也按实际 token 结算。已结算历史记录不重算。DSH 不再因倍率展示文本非数字而阻止请求；模型授权、个人/部门配方、余额准入和幂等结算继续生效。


### 报表图表与导航（2026-11-04）

报表管理包含计费报表和点击率报表两个二级菜单，保留现有 URL 与各自权限。计费配方、增量包管理仍在计费管理中。

点击率报表沿用计费报表的筛选区、四项汇总卡片、折线趋势、横向柱状对比和明细表布局。日期及应用筛选作用于趋势和对比，默认最近 30 天，最长 366 天，结束日期不包含在内；无点击的日期补零。应用、一级分类各显示真实区间点击 Top 8。趋势与区间明细只统计原始点击，不将手工调整虚构成某日新增；日、周、月、年汇总与原有卡片一致，包含手工调整，并在页面说明。

`GET /api/application-registry/click-report` 可选 `from=yyyy-MM-dd`、`to=yyyy-MM-dd`、`applicationId=UUID`，响应新增 `from`、`to`、`trend`、应用筛选选项 `applications` 和每项 `rangeClicks`。数据库直接按北京时间聚合，报表在同一读取快照内生成。真实 PostgreSQL 测试覆盖跨日、补零和手工调整隔离。

门户卡片的四项点击数改为简介下方的轻量行内元信息，移除独立边框与上下两行的数字块，保持明暗主题及窄屏换行。


### 应用集合连续浏览（2026-11-04）

门户卡片移除分页和每页条数选择，改为首次展示 12 张、接近底部时继续追加 12 张的连续浏览。追加保留原有卡片节点，加载完显示全部数量。分类、二级分类、搜索和收藏筛选匹配完整目录，并从首批重新展示；不改变管理表格分页。保留键盘可操作的“加载更多应用”作为手动入口和不支持 IntersectionObserver 时的后备入口。当前目录接口仍一次返回可见应用，分批渲染减少初始卡片数量。
