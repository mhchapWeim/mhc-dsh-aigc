# 附件审查仅记录信息的兼容说明

附件审查保留文件名、文件大小、用户、计算机、会话、Prompt、源路径和时间等信息，不再接收新的文件内容。会话云备份及模型使用本地附件是独立流程。

## 老 DSH 客户端

保留原有 `/v1/uploads` 登记、状态、分片和完成接口。老客户端可继续携带 `sha256` 登记；中台返回原有 `clientUploadId`、`offset`、`bytes`、`completed` 字段。`completed: true` 表示附件记录已保存，老客户端在读取本地文件和检查续传偏移前就结束此任务。只记录信息时 `offset` 为 0，不虚报文件字节已经接收。

原有未完成记录在再次登记、查询状态、提交完成或提交分片时转为信息记录。若升级时客户端已进入分片循环，中台返回 HTTP 410，不读取或保存分片正文；该客户端本次同步可能记录一次失败，下次重试先重新登记并收到完成确认，随后移除任务。无法追回部署前已经发出的网络数据。

历史完整文件及校验值保留，仍按原有管理权限下载。历史 `.part` 文件不再续传，兼容转换不删除它们，也不自动清理完整文件。清理历史文件需另行安排。

## 新 DSH 与页面

新客户端只发送 JSON 信息，不打开附件内容、不发送分片；若后端未确认完成则保留任务等待重试，不回退为内容上传。中台页面保留原有列顺序；信息记录显示进度“—”、状态“已记录”、操作“不可下载”，历史完整文件保持可下载。

## 发布顺序与数据

先发布 AIGC API 和匹配的 Portal，再发布新版 DSH。老 DSH 无须同时升级。新 DSH 提前连接旧 API 时，旧 API 可能拒绝缺少校验值的登记，任务会保留，待中台升级后重试。

不新增数据库列，不执行批量更新：既有 `Sha256` 为空表示信息记录，原有文件上传保留非空校验值；只有经过用户鉴权并访问的未完成任务才按需转换。原有 `(UserId, ClientUploadId)` 唯一约束和记录归属校验保留。

本地验证使用 HTTP 集成测试覆盖老版登记格式、重复登记、各续传入口、权限隔离、历史文件下载及 Range；客户端测试覆盖不读取附件、不发送正文；页面测试覆盖原有列和下载状态。本地通过不代表已部署或真实安装版已验收。
