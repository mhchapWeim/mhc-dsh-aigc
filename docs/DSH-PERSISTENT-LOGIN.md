# DSH 持久登录

SSO 与 AIGC 用户名密码登录均签发独立的访问令牌、持久会话凭据和访问有效期。访问令牌有效期仍为 8 小时；持久会话不因关闭程序、重启电脑或固定时间自动过期。首次使用新版登录后，客户端将凭据存入当前 DSH_HOME 的凭据文件，不保存用户密码，也不保存或重用 CAS ticket。

DSH 启动、身份查询及组织请求会解析有效访问令牌；访问即将过期时，使用持久凭据调用 `POST /v1/auth/refresh` 获取新访问令牌。默认提前 5 分钟续期，运行期间每分钟检查，续期请求超时 10 秒。`llm-managed-backend.sessionTiming` 可配置 `renewBeforeMs`、`pollMs`、`requestTimeoutMs`，均为正整数毫秒数。

网络失败、超时和服务端 5xx 不删除凭据，后续请求重试；侧栏保留已有身份并提示连接异常。启动时尚未确认身份且网络不可用，显示连接异常，不把本地缓存视为已通过服务端认证。账号禁用、会话撤销或明确的身份拒绝才终止会话。

手动退出先删除本地持久凭据和访问令牌，再调用 `/v1/auth/logout` 撤销整个服务端会话；SSO 登录保留原有浏览器 CAS 退出行为。并发续期返回不能恢复已经退出的本地登录。离线退出仍清除本地凭据，但无法保证当时服务端撤销请求到达。

数据库增量新增 `aigc_hub."DshPersistentSessions"` 和 `DshAccessTokens.PersistentSessionId`。服务器仅保存令牌摘要。持久凭据只用于续期及退出，不能调用模型或身份接口；会话撤销使该会话所有访问令牌立即无效。

部署时先更新 AIGC API，再更新 DSH。旧版签发的登录令牌缺少持久凭据，升级后需要重新登录一次；旧客户端仍可使用原访问令牌直到过期。重新安装时若更换或清除 DSH_HOME，不会继承原登录。本次改动不包含安装包和生产部署；内网模型插件源码也已接入有效令牌解析，其独立插件包需要重新构建发布才生效。
